# Source policy

Last reviewed: 2026-09-21

## Source priority

1. Current official Printful developer documentation for API semantics.
2. Current official Printful Help Center/product documentation for production and operational guidance.
3. Clearly dated project snapshots when the user explicitly wants project-specific historical data.
4. General model knowledge only for context, never to override current official Printful information.

## Official source entry points

- Printful developer documentation:
  https://developers.printful.com/docs/
- Printful API v2 preview:
  https://developers.printful.com/docs/v2-preview/
- Printful API v2 beta:
  https://developers.printful.com/docs/v2-beta/
- Printful Help Center:
  https://help.printful.com/

## Freshness rule

Re-check current official information before relying on:
- exact endpoint/version availability;
- request/response fields;
- authentication/header behavior;
- rate limits;
- product/variant IDs;
- stock/availability;
- prices/discounts/taxes/shipping;
- exact print-file requirements;
- supported placements or printing methods;
- current mockup API behavior;
- store/product-management capabilities.

Do not copy large third-party documentation sections into the skill. Prefer original summaries and source links.
